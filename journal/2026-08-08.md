# 2026-08-08 · Project01 마무리 및 회고

📌 Context

Project01 AI Dev Assistant를 MVP 수준에서 최종 마무리하고 실제 배포까지 진행했다.

초기 기능 구현 이후 Prompt Engineering과 사용자 입력 UX를 여러 차례 개선했지만, AI가 사용자가 입력하지 않은 내용을 임의로 보완하지 않도록 제한할수록 결과가 단조로워지는 문제를 확인했다. 반대로 결과를 풍부하게 만들기 위해 추론과 보완을 허용하면 실제 작업과 다른 내용이 생성될 가능성이 있었다.

이 문제를 해결하기 위해 질문과 선택지를 추가하고, 프롬프트 구조를 분리하고, 출력 규칙과 Few-shot 예시를 계속 조정했다. 여러 방향을 시도한 끝에 Prompt만으로 해결하기보다 현재 구현을 MVP로 마무리하고 다음 프로젝트로 넘어가기로 결정했다.

⚖️ Decision

Project01은 추가적인 Prompt 개선보다 현재 기능을 안정적으로 마무리하는 것을 우선하기로 했다.

최종적으로 favicon, metadata, OG 이미지, 모바일 화면, 다크모드, History, Toast, Skeleton UI, Cmd/Ctrl + Enter 단축키 등 전체 기능을 점검하고 Vercel을 통해 실제 서비스로 배포했다.

또한 프로젝트의 한계와 개선 과정 자체를 기록하여, 결과뿐만 아니라 개발 과정에서 내린 판단도 포트폴리오에서 확인할 수 있도록 했다.

🚨 Troubleshooting

### Cmd/Ctrl + Enter 단축키 미동작

특정 textarea의 `onKeyDown`에만 단축키 이벤트가 연결되어 있어, textarea가 렌더링되지 않는 선택형 질문이나 트러블슈팅 단계에서는 단축키가 동작하지 않는 문제가 있었다.

textarea별 이벤트를 제거하고 window 전역 `keydown` 리스너로 통합했으며, ref를 사용해 최신 핸들러와 버튼 상태를 참조하도록 수정했다.

이를 통해 입력 요소의 종류나 현재 포커스 위치와 관계없이 Wizard 내부에서 Cmd/Ctrl + Enter로 주요 동작을 실행할 수 있도록 개선했다.

💭 Retrospective

이번 프로젝트에서 가장 많은 시간을 사용한 부분은 기능 구현보다 Prompt Engineering이었다.

처음에는 Prompt를 개선하면 AI가 사용자의 작업을 더 풍부하게 정리할 수 있을 것이라고 생각했다. 하지만 실제로는 입력 정보가 충분하지 않은 상황에서 AI의 자유도를 높일수록 사실과 추론의 경계가 흐려지는 문제가 발생했다.

반대로 사실에 대한 제약을 강하게 적용하면 사용자가 입력한 짧은 문장을 크게 벗어나지 못해 결과물이 단조로워졌다.

이 과정을 통해 AI 기능의 품질은 Prompt만으로 결정되는 것이 아니라, 사용자가 어떤 정보를 얼마나 쉽게 제공할 수 있도록 제품의 입력 구조를 설계하는지도 중요하다는 것을 경험했다.

이번 프로젝트에서는 이 문제를 끝까지 해결하기보다 MVP 단계에서 범위를 정하고 마무리하는 선택을 했다. 완벽하게 만들기 위해 계속 붙잡기보다 실제 서비스를 배포하고, 한계와 개선 방향을 기록한 뒤 다음 프로젝트에서 더 큰 문제를 다루는 것이 현재 목표에 더 적합하다고 판단했다.
