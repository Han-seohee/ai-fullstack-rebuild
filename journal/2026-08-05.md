# 2026-08-05

## 📌 Context

프로젝트를 마무리하기 전에 전체적인 완성도를 다시 점검했다. 특히 AI가 생성하는 개발일지 품질을 계속 개선하려고 여러 방향을 고민했지만, 입력 정보만으로는 품질을 더 높이는 데 한계가 있다는 점을 확인했다.

## ⚖️ Decision

프롬프트를 계속 수정하는 것보다 현재 수준에서 MVP를 마무리하는 것이 더 가치 있다고 판단했다. 대신 Project01은 여기서 정리하고, 다음 프로젝트에서 더 많은 실제 데이터를 다루며 AI 품질을 개선하는 방향으로 진행하기로 했다.

또한 Cmd/Ctrl + Enter 단축키가 특정 입력 요소에만 의존하지 않도록 이벤트 처리 방식을 전역 keydown 리스너 구조로 변경했다.

## ✅ Outcome

- Cmd/Ctrl + Enter 단축키를 모든 Wizard 단계에서 사용할 수 있도록 수정했다.
- textarea마다 처리하던 keydown 이벤트를 window 전역 이벤트로 통합했다.
- stale closure를 방지하기 위해 ref를 활용하도록 개선했다.
- 프롬프트 개선 방향을 여러 차례 검토한 끝에 현재 프로젝트에서는 과도한 고도화를 멈추고 MVP 단계에서 마무리하기로 결정했다.
- Project01의 마무리 방향과 Project02로 이어질 개발 계획을 구상했다.

## 🚨 Troubleshooting

### 문제

Tooltip은 정상적으로 표시되지만 Cmd/Ctrl + Enter를 눌러도 아무 반응이 없었다. 생성 버튼은 정상적으로 동작했고, 콘솔에도 에러나 로그가 출력되지 않았다.

### 원인

단축키 이벤트가 특정 textarea의 `onKeyDown`에만 연결되어 있었다.

트러블슈팅 단계에서 **'없었어요'**를 선택하면 textarea가 렌더링되지 않아 keydown 이벤트를 받을 요소가 존재하지 않았고, Tooltip은 보이지만 단축키는 동작하지 않는 상황이 발생했다.

### 해결

textarea별 이벤트를 제거하고 `window` 전역 `keydown` 이벤트로 통합했다.

또한 `ref`를 사용해 최신 `handlePrimaryAction`과 버튼 활성 상태를 참조하도록 수정하여 stale closure 문제도 함께 해결했다.

### 배운 점

전역에서 동일하게 동작해야 하는 기능은 특정 입력 요소보다 전역 이벤트로 처리하는 편이 더 안정적이었다.

또한 AI 품질도 프롬프트만 계속 수정한다고 해결되는 것은 아니며, 입력 정보의 양과 구조 자체가 더 중요하다는 점을 다시 느꼈다.
