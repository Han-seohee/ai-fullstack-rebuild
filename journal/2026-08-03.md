# 2026-08-03

## 📌 Context

AI Dev Assistant의 입력 경험을 개선한 뒤 실제로 여러 번 테스트를 진행했다. 테스트 과정에서 AI 결과물의 품질과 사용자 경험을 다시 점검하며 개선이 필요한 부분을 정리했다.

## ⚖️ Decision

트러블슈팅은 AI가 입력되지 않은 내용을 추측해서 작성하면 신뢰도가 떨어진다고 판단했다. 또한 기본/면접용/회고형 결과는 차이가 크지 않아 하나의 결과에 집중하는 방향으로 정리하기로 했다. 커밋 메시지 역시 단순히 첫 번째 작업이 아니라 가장 영향도가 큰 변경을 선택하도록 개선하기로 결정했다.

## ✅ Outcome

AI 결과물에서 부족했던 부분을 구체적으로 확인했고, 트러블슈팅 작성 규칙과 커밋 메시지 생성 방식 개선 방향을 정리했다. 기능을 계속 추가하기보다 결과물의 신뢰성과 완성도를 높이는 단계로 프로젝트 방향을 다듬었다.

## 🚨 Troubleshooting

### 문제

다음 버튼을 눌렀을 때 단계가 넘어가지 않았고, 콘솔에는 폰트 preload 관련 경고가 함께 출력되었다.

### 원인

처음에는 preload 경고가 원인이라고 생각했지만 실제 원인은 `page.tsx`의 `useEffect`였다. `currentStep`이 의존성에 포함되어 있어 단계가 변경될 때마다 effect가 다시 실행되었고, 입력값 비교 과정에서 분석 결과가 초기화되면서 첫 단계로 되돌아가고 있었다.

### 해결

`work.trim()` 기준으로 비교하도록 수정하고 `currentStep`을 effect 의존성에서 제거했다. 또한 분석 완료 시 입력값도 trim하여 저장하도록 변경했다. preload 경고는 별도로 CSS의 폰트 변수 참조를 수정하여 해결했다.

### 배운 점

콘솔에 보이는 경고가 항상 실제 원인은 아니라는 점을 다시 확인했다. 증상과 로그를 그대로 믿기보다 상태 변화와 의존성을 함께 추적하는 것이 더 중요하다는 것을 배웠다.
